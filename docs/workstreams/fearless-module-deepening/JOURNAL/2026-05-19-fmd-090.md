# FMD-090 — Request-side legacy ContentPart adapter extraction

Date: 2026-05-19

## Goal

Land the approved non-breaking FMD-080 proof slice: centralize bridge request normalization's legacy
`ContentPart` construction behind a narrow request-side adapter module without renaming or removing
the public legacy `ContentPart` carrier.

## Red

Added `request_normalization_centralizes_legacy_request_content_constructors` as a source guard.

Command:

```powershell
cargo nextest run -p siumai-bridge --features openai,anthropic,google `
  request_normalization_centralizes_legacy_request_content_constructors --no-fail-fast
```

Result: expected failure before implementation because
`siumai-bridge/src/request/legacy_content.rs` did not exist.

## Implementation

- Added `siumai-bridge/src/request/legacy_content.rs`.
- Moved request-side helper constructors into the adapter module:
  - `request_text_part`
  - `request_reasoning_part`
  - `request_image_part`
  - `request_audio_part`
  - `request_file_part`
  - `request_tool_call_part`
  - `request_tool_result_part`
- Updated OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, and Gemini
  GenerateContent request normalization to call `legacy_content::*`.
- Replaced remaining request-normalization direct legacy constructors for text, reasoning, and tool
  calls so the request-side `provider_metadata: None` invariant lives in one adapter module.
- Preserved the plain-text collapse match in `message_from_parts(...)` as a read/match concern, not
  request construction.
