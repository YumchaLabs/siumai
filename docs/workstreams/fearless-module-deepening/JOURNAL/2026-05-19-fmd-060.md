# 2026-05-19 — FMD-060

## Goal

Split bridge request normalization into a narrower protocol adapter where behavior already varies,
without changing bridge semantics.

## Slice Chosen

Gemini GenerateContent JSON -> `ChatRequest` normalization.

Rationale:

- It was feature-gated and protocol-specific.
- It owned typed Gemini request parsing plus Gemini-only content, tool, tool-config, and generation
  config policy.
- Existing request bridge tests already covered the core projection, and a small source guard could
  prove the policy left the monolithic normalizer.

## Work Completed

- Added `siumai-bridge/src/request/normalize/gemini_generate_content.rs`.
- Moved Gemini typed parser and helpers out of `siumai-bridge/src/request/normalize.rs`.
- Kept public `bridge_gemini_generate_content_json_to_chat_request*` wrappers in `normalize.rs`,
  delegating to `gemini_generate_content::parse_json_to_chat_request(...)`.
- Added `gemini_generate_content_request_normalization_is_protocol_adapter_backed` as a source
  guard.
- Repointed the thought-signature provider-options guard to the new adapter file.

split those common helpers into a dedicated shared request primitive module rather than duplicating
logic.
