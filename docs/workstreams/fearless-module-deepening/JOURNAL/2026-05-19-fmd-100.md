# FMD-100 — Provider public-path parity test locality

Date: 2026-05-19

## Goal

Improve provider-change locality for oversized public facade / parity tests without changing test
semantics or public coverage.

## Assessment

- `public_surface_imports_test.rs` is broad but intentionally acts as a compile-surface import
  guard; it is not provider-flow behavior logic and does not need a split in this slice.
- `provider_public_path_parity_test.rs` was ~47k lines and contained many provider-local modules in
  one file. This was the clear locality hotspot.
- `siumai-registry/tests/factory_architecture_boundary_test.rs` had brittle source slicing against
  the monolithic parity file. It needed a manifest-driven source guard after the split.

## Implementation

- Moved provider-specific modules out of `provider_public_path_parity_test.rs` into
  `siumai/tests/provider_public_path_parity/*.rs`.
- Kept the root test file as the shared harness plus `#[path = ...]` module declarations, so the
  test binary remains `provider_public_path_parity_test`.
- Added registry architecture guards for:
  - requiring provider modules to stay split;
  - reading provider-local module files through a manifest;
  - preserving registry-owned factory and builder shortcut checks after the split.
