# FMD-050 Journal — Registry broad build-helper isolation

Date: 2026-05-19
Task: FMD-050
Status: Complete

## Summary

Production built-in registry factories now avoid the old broad
`registry::factory::build_*_client(...)` generic-client helpers. OpenAI and Anthropic construction
uses private provider-owned typed builders shared by compatibility and native family methods.

The remaining public `registry::factory::build_*_client(...)` helpers are deprecated
compatibility-only shims rather than primary construction paths.

## Key Changes

- `OpenAIProviderFactory::compat_language_client_with_ctx(...)` now reuses
  `build_family_model_with_ctx(...)`.
- `AnthropicProviderFactory` now has a private `build_text_family_model_with_ctx(...)`; both
  compatibility and family-first text construction use it.
- Legacy broad `registry::factory::build_*_client(...)` functions are marked deprecated and
  documented as compatibility-only.
- Public docs and migration notes now direct custom factories to
  `ProviderFactory::*_family_with_ctx(...)` and provider config-first construction.
- `siumai-registry`'s `all-providers` feature now includes `google-vertex`, matching the built-in
  OpenAI-compatible catalog's Google Vertex xAI entry.
- Added source guards for factory helper isolation, deprecated compatibility shims, and the
  `all-providers` manifest invariant.

## Review Notes

No blocking findings remain.

`Option<()>` placeholder parameters remain on the deprecated public helper functions because
removing them would silently change the compatibility shim signature. This is intentionally
documented instead of folded into the family-first path.
