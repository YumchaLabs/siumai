# FMD-040 Journal — Generic-client compatibility isolation

Date: 2026-05-19
Task: FMD-040
Status: Complete

## Summary

`LlmClient` and `ClientWrapper` are now physically owned by `siumai_core::compat::client`.
`siumai_core::client` remains as a lower-level migration alias, while facade and registry users get
explicit compatibility paths through `siumai::compat::client` and
`siumai_registry::compat::client`.

## Key Changes

- Added `siumai-core/src/compat/client.rs` and `siumai-core/src/compat/mod.rs`.
- Replaced `siumai-core/src/client.rs` with a migration-only re-export.
- Removed `siumai_registry::LlmClient` from the registry root and added
  `siumai_registry::compat::client`.
- Added `siumai::compat::client` and kept `siumai::experimental::client` as an advanced alias.
- Updated registry, facade, provider crates, and examples to use explicit compatibility imports.
- Tightened architecture/source guards and migration docs for the new import paths.

## Review Notes

The review found one blocking documentation gap: removing the registry root `LlmClient` alias needed
a concrete migration path. The fix added both public docs and a registry architecture guard for
`siumai_registry::compat::client::LlmClient`.

Provider crate edits were a deliberate scope expansion: leaving local `client` aliases in provider
roots would keep broad generic-client compatibility imports alive outside the explicit compat seam.
