# 2026-05-19 — FMD-020 provider-defined tool catalog extraction

## Claim

FMD-020 is complete: provider-defined hosted-tool catalogs are no longer canonically owned by
`siumai-spec` or `siumai-core`; passive `Tool::ProviderDefined` data shapes remain stable in spec;
protocol/provider crates now own concrete catalog facts.

## Architecture Changes

- Removed root catalog ownership:
  - deleted `siumai-spec/src/tools.rs`
  - deleted `siumai-core/src/tools.rs`
  - removed root `pub mod tools` exports from spec/core
- Preserved passive spec data:
  - kept `siumai-spec::types::tools`
  - removed catalog lookup helpers from spec data carriers
- Added owning catalogs:
  - `siumai-protocol-openai/src/tool_catalog.rs`
  - `siumai-protocol-anthropic/src/tool_catalog.rs`
  - `siumai-protocol-gemini/src/tool_catalog.rs`
  - `siumai-provider-groq/src/tools.rs`
  - `siumai-provider-xai/src/tools.rs`
- Kept public compatibility:
  - `siumai::tools::*` re-exports protocol/provider-owned helpers
  - facade-only `siumai::tools::provider_defined_tool(id)` aggregates enabled catalogs

## Review Notes

No blocking workstream-compliance or code-quality findings remain.

One intentional scope expansion occurred: Groq/xAI provider crates and Google Vertex call sites were
included because the old spec catalog owned their provider facts and downstream users needed to
follow the new ownership seam. This is consistent with FMD-020's provider-residue-removal goal.
