# 2026-05-19 — PRG-070 Provider-Owned Response Parsers

## Goal

Audit provider-owned response parsers outside the pure protocol modules and decide whether they
should adopt local response adapters or remain provider-owned exceptions.

## Audit Notes

- Google Interactions is a provider-owned API surface under `siumai-provider-gemini`; it parses
  interaction steps, built-in tool calls/results, citations, images, signatures, and interaction
  metadata. It is separate from the pure Gemini GenerateContent protocol parser.
- Bedrock chat is a mixed request/response file. The response transformer is narrow enough to
  extract safely, but request conversion should remain out of this lane.
- Bedrock streaming reconstructs a final `ChatResponse` from accumulated stream blocks. That
  final-response construction is response-side compatibility work; event emission itself remains
  stable `ChatStreamPart` primitives.

## Decision

- Adopt provider-local `response_content` adapters for:
  - Google Interactions response parsing;
  - Bedrock non-stream response parsing;
  - Bedrock stream final-response aggregation.
- Do not expand PRG-070 into broad Bedrock request cleanup.
- Do not force generated-output projection from provider-owned parsers.

## Changes

- Added `siumai-provider-gemini/src/providers/gemini/interactions/response/response_content.rs`.
- Updated Google Interactions response parser to delegate legacy response compatibility content
  construction to the local adapter.
- Added `siumai-provider-amazon-bedrock/src/standards/bedrock/chat/response_content.rs`.
- Updated Bedrock response transformer and stream final-response aggregation to use the local
  adapter.
- Strengthened Bedrock and Google Interactions source guards for:
  - adapter delegation;
  - request-provider-options hygiene;
  - no direct generated-output projection.
