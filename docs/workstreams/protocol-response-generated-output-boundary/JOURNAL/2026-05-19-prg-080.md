# PRG-080 — Public docs for response adapters and generated-output projection

Date: 2026-05-19
Status: DONE

## Scope

- `docs/architecture/public-surface.md`
- `docs/migration/migration-0.11.0-beta.7.md`
- `docs/workstreams/protocol-response-generated-output-boundary`

## Work performed

- Added public-surface guidance that response parsers may still emit legacy `ChatResponse` /
  `MessageContent` payloads for compatibility, but `ContentPart` is not the canonical response
  model.
- Clarified that parser-local `response_content` modules are internal compatibility adapters that
  own empty request-side `provider_options` defaults and preserve response-side
  `provider_metadata`.
- Clarified in the beta.7 migration guide that spec-owned generated-output projection helpers are
  separate from parser-local compatibility adapters and are intentionally fallible.
- Documented that hosted tool results, approval requests, files, images, audio, or provider-specific
  metadata should remain `ChatResponse` compatibility payloads unless lossless projection is proven.

## Decisions

- No new public generated-output response model was introduced in this task.
- Future public response model work still requires an ADR-backed follow-on.

## Validation

- JSON and docs source-guard checks recorded in `EVIDENCE_AND_GATES.md`.
- No Rust crate tests were run because PRG-080 changed documentation and workstream metadata only.
