# 2026-05-19 — PRG-060 Bridge Response/Stream Ownership

## Goal

Audit `siumai-bridge/src/response` and `siumai-bridge/src/stream` and decide whether bridge
response/stream paths should use protocol response adapters, stay primitive-only, or split a
narrower follow-on.

## Audit Notes

- `response/serialize.rs` orchestrates clone/remap/hook/inspect/reject/encode flow and delegates
  target JSON encoding through `target_dispatch.rs`.
- `response/inspect.rs` and `response/target_caps.rs` are target capability and loss-reporting
  logic; they do not parse provider responses or construct response compatibility content.
- `stream/serialize.rs` applies stream hooks/remappers, optionally inserts the OpenAI Responses
  stream replay shim, normalizes terminal events, and delegates target SSE encoding.
- `stream/openai_responses_parts_bridge.rs` is intentionally narrower than a provider response
  parser: it upgrades stable/custom stream parts and adds replay raw items for downstream SSE
  converters.
- `target_dispatch.rs` is the correct bridge/protocol seam: protocol crates own request
  transformers, response JSON converters, and SSE event converters.

## Decision

Keep bridge response/stream paths primitive-only:

- public inputs remain `ChatResponse` and `ChatStreamEvent`;
- outputs remain target JSON/SSE bytes or values;
- provider-specific preservation/loss is surfaced through `BridgeReport`;
- parser-local protocol `response_content` adapters are not used by bridge;
- generated-output projection helpers are not called from bridge.

If gateway/proxy JSON or SSE replay needs richer provider semantics later, split a narrower
follow-on instead of expanding bridge into the canonical owner of provider response semantics.

## Changes

- Added source guard helpers in `siumai-bridge/src/response/tests.rs`.
- Added guards proving bridge response/stream/dispatch code:
  - does not call generated-output projection helpers directly;
  - does not couple to parser-local `response_content` adapters.
- Updated `TODO.md`, `EVIDENCE_AND_GATES.md`, `HANDOFF.md`, and `WORKSTREAM.json`.
