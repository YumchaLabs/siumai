# PRG-040 Journal — Anthropic Response Adapter Proof

Date: 2026-05-19
Status: DONE

## Scope

- `siumai-protocol-anthropic/src/standards/anthropic/utils/parse.rs`
- `siumai-protocol-anthropic/src/standards/anthropic/utils/parse/response_content.rs`
- `docs/workstreams/protocol-response-generated-output-boundary/*`

## Work Performed

- Audited Anthropic response parsing for response-side legacy `ContentPart` construction.
- Added parser-local `response_content` adapter for Anthropic response compatibility payloads.
- Moved text, reasoning, source, tool-call, tool-result, and nested tool-result text part
  construction behind adapter helpers.
- Preserved Anthropic citation/source/tool-use semantics:
  - text citations stay under Anthropic provider metadata;
  - URL/document source parts retain Anthropic source metadata and the separate `AnthropicSource`
    list;
  - server tool caller/original-name metadata and MCP server-name metadata remain response-side;
  - request-side provider options remain empty compatibility defaults only.
- Added source guards for adapter delegation, request-provider-options hygiene, and no direct
  generated-output projection.

## Key Decision

Anthropic does not need a generic cross-provider adapter. Its citations, source list, hosted tools,
and MCP metadata remain provider-owned, but construction is now localized behind a named
response-content adapter so future generated-output projection work can reason about lossiness
explicitly.
