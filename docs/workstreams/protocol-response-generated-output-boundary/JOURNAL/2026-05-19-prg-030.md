# PRG-030 Journal — OpenAI Responses Generated-Output Lossiness

Date: 2026-05-19
Status: DONE

## Scope

- `siumai-protocol-openai/src/standards/openai/transformers/response/responses.rs`
- `docs/workstreams/protocol-response-generated-output-boundary/*`

## Work Performed

- Classified OpenAI Responses response shapes by whether the current compatibility payload can be
  projected to `GenerateTextContentPart` without loss.
- Added a production source guard ensuring OpenAI Responses parsing and the local
  `response_content` adapter do not call generated-output projection helpers directly.
- Added behavior coverage for:
  - lossless projection of text + reasoning + function-call response content;
  - rejection of MCP approval requests;
  - rejection of output-only hosted tool results that lack original input.
- Recorded the lossiness matrix and fresh verification results in `EVIDENCE_AND_GATES.md`.

## Key Decision

Generated-output projection remains a fallible, spec-owned boundary. OpenAI Responses parsing may
feed only proven-lossless subsets through it; ambiguous approval, file/image/audio, output-only
tool-result, and full response metadata paths remain legacy response compatibility payloads.
