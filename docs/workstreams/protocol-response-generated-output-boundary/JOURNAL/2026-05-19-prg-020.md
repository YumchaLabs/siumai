# PRG-020 — OpenAI Responses Response Compatibility Adapter

Date: 2026-05-19

## Goal

Extract OpenAI Responses response-owned legacy `ContentPart` construction behind a named response
compatibility adapter module without changing serialized output.

## Work Performed

- Added
  `siumai-protocol-openai/src/standards/openai/transformers/response/responses/response_content.rs`.
- Routed response-side text, reasoning, custom, source, tool call, tool result, and tool approval
  request construction through `response_content::*`.
- Moved the final `MessageContent` compatibility wrapping decision into the adapter.
- Added source guards proving:
  - `responses.rs` delegates legacy content construction to the adapter;
  - `response_content.rs` owns only empty legacy request-provider-option defaults.

## Validation

Passed:

```text
cargo fmt --check -p siumai-protocol-openai
cargo nextest run -p siumai-protocol-openai --no-default-features --features openai-standard,openai-responses responses_response_transformer_source_does_not_emit_request_provider_options --no-fail-fast
cargo nextest run -p siumai-protocol-openai --no-default-features --features openai-standard,openai-responses standards::openai::transformers::response::responses::tests --no-fail-fast
cargo check -p siumai-protocol-openai --no-default-features --features openai-standard,openai-responses
```
