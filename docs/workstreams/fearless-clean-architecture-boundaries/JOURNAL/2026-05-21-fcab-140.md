## Summary

FCAB-140 ran the integration sweep for the fearless clean-architecture lane. The preferred bash smoke
path was not usable in this PowerShell/Windows terminal because `bash` resolves to
`C:\Windows\system32\bash.exe` and timed out before script output. The lane therefore used a
documented PowerShell/provider-dependency scan and an explicit `cargo nextest` matrix as the smoke
substitute.

## Findings And Fixes

- `cargo fmt --all -- --check` fails on this Windows workspace with `文件名或扩展名太长。 (os error
  206)`, so FCAB-140 used per-package formatting checks instead.
- `scripts/check-provider-deps.sh` still treated every `siumai-provider-*` crate as a forbidden
  provider dependency. FCAB-090/100 intentionally introduced `siumai-provider-utils` as the shared
  provider/protocol utility seam, so the script now allows `siumai-provider-utils`.
- The facade architecture suite exposed stale guard assumptions:
  - the FCAB seam inventory guard now requires the audited core utility paths that were split into
    provider-utils;
  - the content audit guard now includes this workstream's `content-part-adapter-audit.md`;
  - the historical `prelude::registry` mirror assertion now scopes itself to the compatibility
    prelude instead of matching the stable `prelude::unified::registry` module.
- Azure OpenAI chat request normalization was cleaned up to use the local `provider_utils` owner path
  and pass formatting.
