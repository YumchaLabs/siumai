# FCAB-090 Journal — Provider-Utils First Crate Slice

Date: 2026-05-21

## Scope

FCAB-090 implemented the first provider-utils isolation step as a real crate:
`siumai-provider-utils`.

## Architecture Decision

Chose a new crate rather than a deep internal module because:

- URL, MIME, builder-default, and chat request normalization helpers already had multiple
  provider/protocol callers.
- The new crate can depend on `siumai-spec` instead of `siumai-core`, avoiding a dependency cycle.
- `siumai-core` can keep compatibility aliases for older imports while provider/protocol crates move
  to a visible provider-utils seam.

## Implementation

- Added workspace crate `siumai-provider-utils`.
- Moved implementations for:
  - `builder_helpers`
  - `chat_request`
  - `mime`
  - `url`
- Converted old `siumai-core::utils::{builder_helpers, chat_request, mime, url}` files into
  compatibility aliases.
- Added internal `crate::provider_utils` aliases to registry/provider/protocol crates and rewired
  high-churn call sites away from `crate::utils`.
- Added source guard `provider_utils_crate_owns_high_churn_provider_helpers`.
- Documented the crate in `docs/architecture/module-split-design.md`.
