# FCAB-070 Journal — Directional Content Exports

Date: 2026-05-21

## Summary

Completed the export/facade half of the directional content seam.

- Added `siumai-spec::types::content::{prompt, output, compat}`.
- Inherited the same directional namespaces through `siumai-core::types`.
- Added facade namespaces `siumai::content::{prompt, output, compat}`.
- Added stable-prelude navigation modules `siumai::prelude::unified::{prompt, output}`.
- Kept legacy `ContentPart` out of `prelude::unified`; migration code must use
  `siumai::compat::content::ContentPart`, `siumai::content::compat::ContentPart`, or
  `siumai::prelude::compat::content::ContentPart`.

## Implementation Notes

- Updated public-surface and migration docs to describe directional imports.
- Added facade architecture guards:
  - `directional_content_namespaces_are_visible_and_compat_is_explicit`
  - `tests_and_examples_do_not_import_legacy_content_part_from_unified_prelude`
- Updated public-surface compile tests for `siumai::content::{prompt, output, compat}`.
- Repointed tests and `siumai-extras` code that still intentionally consumes legacy chat content
  to explicit compat imports.

## Handoff To FCAB-080

FCAB-080 should now move production direct `ContentPart` construction behind named request or
response adapters. A first scan shows the highest-value starting points are:

- `siumai-bridge/src/response/inspect.rs`
- `siumai-protocol-anthropic/src/standards/anthropic/json_response.rs`
- `siumai-protocol-gemini/src/standards/gemini/convert.rs`
- `siumai-provider-gemini/src/providers/gemini/interactions/{request,response}.rs`
- provider metadata helpers that pattern-match legacy content for extension extraction should be
  classified separately from response-construction adapters.

Keep request adapters from reading response `provider_metadata`, and keep response adapters from
emitting request `provider_options` except documented empty legacy defaults.
