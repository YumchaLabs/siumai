# 2026-05-21 — FCAB-060

## Task

OpenAI-compatible vendor Module cleanup:

- keep promoted OpenAI-compatible vendors focused on presets, quirks, typed options, metadata, and
  facade extension exports;
- remove TogetherAI image runtime ownership from the registry factory;
- keep registry logic limited to provider resolution, build overrides, and typed-client projection.

## Implementation Summary

- Added `siumai-provider-togetherai/src/providers/togetherai/image.rs`.
- Moved TogetherAI image generation/edit request mapping, provider option merging, size parsing,
  edit mask validation, response parsing, warnings, HTTP execution, and model metadata into the
  TogetherAI provider crate.
- Added `siumai-provider-togetherai/src/standards/togetherai/headers.rs` and reused it for both
  TogetherAI rerank and image specs.
- Added `TogetherAiConfig::DEFAULT_IMAGE_MODEL`, `TogetherAiConfig::image_config_for_model`, and
  `TogetherAiBuilder::build_image_model`.
- Rewired `siumai-registry/src/registry/factories/togetherai.rs` so it imports
  `TogetherAiImageClient` from `siumai-provider-togetherai` and only builds/projects provider-owned
  image/rerank clients plus shared OpenAI-compatible text/audio clients.
- Exposed `TogetherAiImageClient` through `siumai::provider_ext::togetherai`.
- Added source guard `togetherai_provider_crate_owns_image_runtime`.
- Extended public path parity with
  `togetherai_provider_owned_image_client_matches_unified_public_path`.
