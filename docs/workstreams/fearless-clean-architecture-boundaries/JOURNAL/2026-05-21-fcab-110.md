# FCAB-110 Journal — Bridge Target Adapter Deepening

Date: 2026-05-21

## Scope

FCAB-110 started the bridge-target adapter ownership cleanup. The goal was to move target-specific
wire parsing out of `siumai-bridge` when a protocol crate can own it without depending on bridge
reports, loss policy, hooks, or lifecycle.

## Implementation

- Moved Gemini GenerateContent JSON request normalization from
  `siumai-bridge/src/request/normalize/gemini_generate_content.rs` into
  `siumai-protocol-gemini/src/standards/gemini/request_bridge.rs`.
- Kept the bridge file as a thin compatibility shim that delegates to the protocol-owned adapter.
- Exported `request_bridge` from `siumai-protocol-gemini::standards::gemini`.
- Refreshed Gemini bridge source guards so they read the protocol-owned adapter and prove the shim
  delegates to `siumai-protocol-gemini`.
- Documented retained bridge-owned direct-pair/normalization adapters in
  `bridge-target-adapter-audit.md`.
- Adjusted OpenAI built-in tool ID fallback helpers in bridge normalization so the bridge can still
  compile with only the `google` feature; canonical IDs are used when `openai` is enabled.

## Validation

See `EVIDENCE_AND_GATES.md` for command evidence.

## Follow-up

FCAB-120 can proceed to facade/public-surface tightening. Additional bridge adapter moves should be
one adapter at a time and should not move bridge loss/replay policy into protocol crates.
