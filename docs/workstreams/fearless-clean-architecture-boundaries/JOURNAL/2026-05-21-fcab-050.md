# 2026-05-21 — FCAB-050

## Task

OpenAI-compatible protocol/runtime/vendor deepening, first slice:

- make OpenAI-compatible completion response conversion protocol-owned;
- make OpenAI-compatible completion SSE parser state protocol-owned;
- keep provider runtime focused on HTTP execution, capability routing, and runtime warnings;
- preserve native OpenAI provider behavior.

## Implementation Summary

- Added `siumai-protocol-openai/src/standards/openai/compat/completion.rs`.
- Moved OpenAI-compatible completion response materialization, provider metadata attachment, usage
  policy application, finish-reason parsing, SSE parser state, raw-chunk emission, and terminal
  metadata emission into the protocol layer.
- Rewired
  `siumai-provider-openai-compatible/src/providers/openai_compatible/openai_client/completion/mod.rs`
  to delegate through protocol-owned `CompletionResponseConversion` and `CompletionSseConverter`.
- Deleted the provider runtime's local `completion/streaming.rs` parser module.
- Added source guards in `siumai-protocol-openai/tests/openai_compat_boundary_test.rs` proving:
  - protocol owns the OpenAI-compatible completion converter and parser state;
  - provider runtime imports protocol conversion and does not re-own parser state or finish-reason /
    usage policy logic;
  - native OpenAI keeps its provider-specific completion converter.
